# Research recovery and strong-result contract

Read at startup and before any experiment correction. This is the single revision policy for this skill, its experiment-completion template, guidance specification and paper-production references.

## Authorized redesign

Record the original method family, target tier, public-data rules and measured resource envelope in the execution contract. Required CCFA optimizer/searcher/designer/reviewer/auditor transitions and in-scope repairs are included in the requested research pipeline. Sibling handoff defaults must not create repeated approval questions for these prescribed actions.

P1A/P1B/P3A/P4/P5/P5A failures open a correction record, not permission to write. Classify the defect and earliest affected gate; record prior attempt, evidence, next hypothesis, changed variables, falsifier, predicted cost, and remaining search/compute budget. Repair an implementation error locally; use CCFA redesign when the mechanism, scenario, baseline or evidence plan is affected. Do not force every numeric typo through full idea generation.

Within the recorded scope, create an immutable replacement guidance version automatically. Preserve prior contracts and negative results. Never lower the same measured target because it failed: a replacement must have a genuinely revised mechanism/task/evidence plan, fresh baseline calibration, and its own binding expected_strong criterion. Mark the old direction superseded, update the execution contract, reopen from P0, and reaccept all stages in order. Verified unaffected artifacts can be reused with explicit applicability evidence; do not rerun expensive unchanged work merely to refill a stage row.

Request direction only for a new method family, changed target tier, inaccessible/private/paid data, extra resources, external execution or other material scope expansion. Before asking, complete the authorized diagnosis and present concrete options with cost and evidence. A supplied guiding file stays an immutable input; put revisions in the run root.

## Strong evidence and bounded search

Keep the P5 strong-result lock: all required experiments complete, strongest feasible baselines supported, real main-claim results meet the current contract, and uncertainty/ablations support the claim. A falsifying ablation or negative control should meet its planned evidentiary outcome; it need not outperform the full method. No fabricated numbers, cherry-picked seeds or omitted failed trials.

Before tuning, freeze train/validation/test split identities, primary metrics/direction, seed policy and the evaluation protocol. Tune on training/validation only. Log all trials and select the final method without using held-out test performance for search. Evaluate the frozen selection on the final test. If a test result informed redesign, label that test as exposed, preserve its history, and use a justified new holdout/external confirmation or explicitly account for adaptive evaluation; never relabel it as unseen.

Set numeric trial, runtime and resource limits from the actual project budget before a campaign. Do not repeat an identical failed route without new evidence. On budget exhaustion or repeated non-improvement, close that campaign with a failure analysis and screen a materially different feasible candidate within the remaining authorized envelope. Do not silently reset the total budget. If no eligible route remains, retain a resumable blocked state with the exact missing decision; automation must not simulate progress or loop indefinitely.

## Early dependencies and output policy

At P0/P2 inspect the actual installed AutoResearchClaw version and documented CLI/stage interfaces using local help or source. Map semantic stages PAPER_OUTLINE through CITATION_VERIFY to the installed IDs; verify configured provider/model, supported arguments, output paths and availability without exposing credentials. Do not assume this chat's Astra selection propagates to the CLI. No automatic paid API test. Unsupported dependencies must be resolved before the full training campaign, within existing authorization, or surfaced as a concrete compatibility blocker. Never silently replace required review stages with a one-pass draft.

Keep paper structure, citation scope, figure, and page preferences in the run contract. Preserve the six-section outline; derive reference scope from the research question and venue, visuals from evidence, and manuscript length from venue rules or author preference. With neither a length rule nor preference, do not impose a numeric page target. Current official journal limits govern.
