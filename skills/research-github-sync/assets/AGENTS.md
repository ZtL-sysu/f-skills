## 协作文档位置

- `collaboration/STATE.md`：目标、当前阶段、已验证/假设/被推翻结论、关键决策、下一步
- `collaboration/TASKS.md`：任务状态、负责人、范围
- `collaboration/agents/<agent_id>.md`：各 Agent 的交接记录

## 接续规则

1. **开始**：按顺序读 `AGENTS.md` → `STATE.md` → `TASKS.md` → 相关 `agents/*.md`，先形成简短的项目认知摘要；再按任务需要读源码、配置、结果、论文或历史记录。不要一进项目就全盘扫描。
2. **核实**：旧计划、旧 README、旧日志只作背景；当前状态以 STATE.md 为准，重要结论必须核对实际证据文件。日志里写着「运行中」不等于进程还活着。
3. **认领**：在 TASKS 标 `doing` 并写范围；发现别人 `doing` 的重叠范围先避开。任务状态是记录，不是进程锁。
4. **结束（必做）**：更新 TASKS 里自己任务的状态，并写或更新自己的 `agents/<id>.md`（含可执行的 Resume Entry）。没有分配身份时自己取一个可区分的 ID（工具名+日期）。更新任务状态不算改动项目级共识，不要因此跳过；对项目级结论有疑问就写进自己的记录，不要改写 STATE。只改任务相关文件，不改其他 Agent 正在处理的文件。
5. **Git**：只显式 stage 本次产物，正常 commit / push，不 force push、不 `reset --hard` / `git clean`、不覆盖他人未提交修改、不上传凭证与大文件。
